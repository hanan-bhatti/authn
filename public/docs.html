Prerequisites

  • Node.js ≥ 16.0.0
  • npm ≥ 8.0.0
  • MongoDB 5+ (Atlas or self-hosted)
  • SMTP provider — Gmail, Mailgun, SendGrid, etc.
  • Optional: Firebase project (for Google OAuth)
  • Optional: AWS S3 / Filebase (for avatar storage)

Quick Start

1 — Clone the repository

git clone https://github.com/hanan-bhatti/authn.git
cd authn

2 — Install dependencies

npm install

3 — Configure your environment

cp .env.example .env
# Open .env and fill in your values (see Configuration section)

4 — Start the server

npm start        # production
npm run dev      # development (hot-reload via nodemon)
💡
The server listens on PORT (default 5000). Your API base URL is http://localhost:5000/api.

⚠️
Never commit .env to version control. The .gitignore already excludes it.

Database Setup

Authn uses MongoDB via Mongoose. Any MongoDB 5+ deployment works — MongoDB Atlas is the easiest option.

  1. Create a free cluster at cloud.mongodb.com.
  2. Add a database user and whitelist your IP (or 0.0.0.0/0 for development).
  3. Copy the connection string and set MONGODB_URI in .env.

Authn auto-creates all collections and indexes on first start — no migration scripts needed for a fresh install.

Email Configuration

Authn sends transactional emails for:

  • Email verification OTP (6 characters, 10-minute expiry)
  • Password reset links (30-minute expiry)
  • New device detection alerts
  • Security event notifications

Gmail quick-start

  1. Enable 2-Step Verification on your Google account.
  2. Create an App Password (Google Account → Security → App passwords).
  3. Use that password as SMTP_PASS.
ℹ️
For production, prefer a dedicated transactional email service like Mailgun, SendGrid, or Postmark to avoid Gmail sending limits.

Authentication Flows

Registration

  1. POST /api/auth/register with { email, username, password, fullName }
  2. Server creates user, sends OTP to email, returns 201 with JWT.
  3. Client calls POST /api/auth/verify-email with the OTP.

Login

  1. POST /api/auth/login with { identifier, password } (identifier can be email or username).
  2. If 2FA is enabled, server responds with requiresTwoFactor: true.
  3. Client calls POST /api/auth/verify-2fa with the TOTP code.
  4. If device is unrecognised, user receives a device-verification email.

Password Reset

  1. POST /api/auth/forgot-password — sends a reset link.
  2. POST /api/auth/reset-password — validates token, sets new password, terminates all sessions.

JWT Tokens

Authn issues HS256-signed JWTs. Tokens are sent via HttpOnly cookie and optionally via Authorization: Bearer <token> header.

// Token payload example
{
  "userId": "...",
  "sessionId": "...",
  "role": "user",
  "iat": 1700000000,
  "exp": 1700604800
}

Tokens are validated against the session record on every protected request. Revoking a session immediately invalidates its token.

Google OAuth 2.0

Authn uses the Firebase Admin SDK to verify Google ID tokens sent from the client.

Setup

  1. Create a Firebase project at console.firebase.google.com.
  2. Enable Google Sign-In in Authentication → Sign-in methods.
  3. Generate a service account key (Project Settings → Service Accounts).
  4. Set the Firebase env vars in .env.

Flow

  1. Client authenticates with Google and gets an ID token.
  2. Client sends POST /api/auth/google with { idToken }.
  3. Server verifies the token, creates/links the user, returns a JWT session.

Two-Factor Authentication

Authn implements RFC 6238 TOTP (the same standard used by Google Authenticator, Authy, and 1Password).

Enable 2FA

  1. POST /api/auth/2fa/setup — server returns a otpauth:// URI and QR code data URL.
  2. User scans the QR code in their authenticator app.
  3. POST /api/auth/2fa/enable with { token } — verifies and activates 2FA.

Backup codes

8 alphanumeric one-time backup codes are generated on setup. Each code can only be used once. Regenerate at any time via POST /api/auth/2fa/backup-codes/regenerate.

Rate limiting

5 failed 2FA attempts trigger a 15-minute lockout on that account.

Device Management

Authn fingerprints each device using browser, OS, IP, and geolocation data, generating a unique SHA-256 device ID.

  • Up to 10 trusted devices per user.
  • New devices trigger an email alert with a 24-hour verification token.
  • Devices inactive for 90 days are automatically removed.

Key endpoints

GET  /api/devices              — list all devices
POST /api/devices/verify        — verify a new device
POST /api/devices/:id/trust     — mark as trusted
DELETE /api/devices/:id         — remove a device

Session Management

Up to 5 concurrent active sessions per user. Oldest session is terminated when the limit is exceeded.

Key endpoints

GET    /api/sessions             — list all active sessions
DELETE /api/sessions/:id         — revoke a specific session
DELETE /api/sessions             — revoke all sessions (logout everywhere)
POST   /api/auth/logout          — logout current session

RBAC & Permissions

Authn ships with a 4-tier role system:

user  →  moderator  →  admin  →  superadmin

Each role inherits all permissions of the roles below it. Roles are stored on the User model and checked via the authorize(...roles) middleware.

Protecting routes

// In your Express route file:
const { protect, authorize } = require('./middleware/auth');

router.get('/admin/users', protect, authorize('admin', 'superadmin'), handler);

Automated Backups

  • Pre-deletion backups — mandatory before account deletion.
  • Scheduled backups — via node-cron (configurable interval).
  • Encryption — AES-256 optional encryption.
  • Compression — Gzip by default.
  • Retention — 365 days (configurable).

Manual trigger

POST /api/backup/trigger     — create a manual backup
GET  /api/backup/status      — check backup service status

Rate Limiting

  • Global API: 1 000 requests / 15 minutes
  • Auth endpoints: 5 requests / 15 minutes
  • Account lockout: 10 failed logins → 30-minute lockout
  • 2FA lockout: 5 failed attempts → 15-minute lockout

Rate-limit headers are always returned:

X-RateLimit-Limit: 1000
X-RateLimit-Remaining: 999
X-RateLimit-Reset: 2025-01-01T00:15:00.000Z

Deployment

Traditional VPS / Server

git clone https://github.com/hanan-bhatti/authn.git
cd authn && npm install --production
cp .env.example .env  # configure
NODE_ENV=production npm start

# Keep it running with PM2
npm install -g pm2
pm2 start server.js --name authn
pm2 save && pm2 startup

Heroku

heroku create my-authn-app
heroku config:set $(cat .env | xargs)
git push heroku main

Docker

docker build -t authn .
docker run -d -p 5000:5000 --env-file .env authn
⚠️
Always set NODE_ENV=production, use a strong JWT_SECRET, and serve behind HTTPS (nginx / Caddy / Cloudflare).

Security Guide

  • HTTP headers hardened with Helmet (CSP, XSS, Clickjacking, MIME sniffing).
  • Passwords hashed with bcryptjs at 12 salt rounds.
  • JWTs signed with HS256 and validated on every request.
  • CORS restricted to whitelisted origins via CORS_ORIGIN.
  • All auth events recorded in the audit log.
  • Sensitive fields (password, tokens, backup codes) excluded from API responses via Mongoose select: false.
  • Account deletion anonymises data before removal.

To report a security vulnerability, email hannanbhatti2006@gmail.com with subject [SECURITY]. Do not open a public issue.

FAQ

Can I use Authn without Google OAuth?

Yes. Simply leave the Firebase environment variables empty. The Google sign-in endpoint will return an error if called, but all other features work normally.

How do I add a new OAuth provider?

GitHub, Facebook, Twitter, and LinkedIn support is planned for Q2 2025. In the meantime you can implement a custom strategy following the Google OAuth pattern in routes/auth.js.

Where are avatars stored?

Avatars are processed with Sharp (resized, converted to WebP) and uploaded to Filebase (IPFS-backed S3-compatible storage). Set FILEBASE_* env vars to enable this feature.

Is there an admin UI?

An admin dashboard UI is on the roadmap. Currently, admin operations are performed via the API with an admin or superadmin role token.

How do I run the tests?

npm test
